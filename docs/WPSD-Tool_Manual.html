Philosophie & Konzept

WPSD ist eine hervorragende und mächtige Dashboard-Plattform für digitale Hotspots. Es hat jedoch eine architektonische Eigenheit: Bei Speicherungen im Web-Interface werden oft individuelle Routing-Entscheidungen (wie manuell angelegte statische Talkgroups oder erweiterte Rewrite-Regeln) im Hintergrund gnadenlos überschrieben oder gelöscht.

Dieses WPSD - Gateway Tool gibt dem Funker die volle Kontrolle über sein Gateway zurück. Es agiert als echter Watchdog (Wächter): Es analysiert die Konfiguration tiefgreifend bis auf die Dateisystemebene, deckt unautorisierte Änderungen auf und ermöglicht die sofortige Wiederherstellung einer gesicherten Master-Konfiguration. Du kannst WPSD endlich "unter die Haube" schauen und exakt verstehen, wie dein Traffic geroutet wird.

Zero-Overhead Architektur: Das gesamte Tool besteht aus einem einzigen, hochoptimierten Bash-Skript. Es benötigt keine Datenbanken, keine ressourcenfressenden Hintergrunddienste (Dämonen) und keine externen APIs. Der Ressourcenverbrauch (CPU/RAM) auf dem Hotspot liegt bei exakt 0%, wenn das Tool nicht gerade aktiv vom Benutzer aufgerufen oder einmalig in der Nacht durch den winzigen Cronjob getriggert wird.

Experimenteller Charakter: Dieses Tool greift aktiv in das Dateisystem und die Dienste des Hotspots ein. Die Nutzung erfolgt ausdrücklich auf eigene Gefahr.

ZWINGEND ERFORDERLICH: WPSD System-Backup

Bevor du dieses Tool installierst und das erste Mal ausführst, muss dein WPSD-System absolut fehlerfrei funktionieren. Das Tool legt beim ersten Start eine Master-Kopie deiner aktuellen Konfiguration an. Ist diese bereits fehlerhaft, sicherst du den Fehler mit ab!

Führe jetzt zwingend diese Schritte im WPSD Web-Dashboard aus:

  1. Klicke oben im Menü auf Admin
  2. Wähle Advanced
  3. Klicke im Tools-Menü auf Datensicherung (Backup/Restore)
  4. Lade das ZIP-Archiv herunter und lege es sicher auf deinem Computer ab.

Deployment & Installation

Die Installation erfolgt aus unserem zentralen GitHub-Repository direkt auf deinen Hotspot. Dadurch stellst du sicher, dass du immer den getesteten und fehlerfreien Code-Stand erhältst.

  1. Öffne ein Terminal (SSH) und logge dich als Benutzer pi-star auf deinem Hotspot ein.
  2. Lade das Tool mit dem wget-Befehl aus dem Netz.
  3. Mache die Datei ausführbar (chmod +x).
  4. Starte das Tool einmalig, um das Master-Backup initial zu erzeugen.
# 1. Datei von GitHub laden
wget https://raw.githubusercontent.com/BurnedOak/wpsd-tool/main/dmr-chk
# 2. Ausführungsrechte setzen
chmod +x dmr-chk
# 3. Erster Start (Master-Backup anlegen)
./dmr-chk

Bedienung: Wächter & Analyse

Der Wächter-Modus

Das Skript wird im Terminal des Hotspots durch die simple Eingabe von ./dmr-chk aufgerufen. Es vergleicht sofort die aktive Systemdatei mit deiner hinterlegten Master-Kopie.

Szenario A: Keine Änderungen

Wenn WPSD nichts überschrieben hat, meldet das System sofort:
[OK] Keine unautorisierten Änderungen in dmrgateway gefunden.
Szenario B: Abweichung erkannt!

Das Skript schlägt Alarm und bietet ein Aktions-Menü:
[D]iff : Änderungen farbig anzeigen
[R]estore : Master-Backup wiederherstellen
[U]pdate : Aktuelle Datei als Master speichern
[I]gnore : Nichts tun und beenden (Test-Modus)

Wählst du [R], repariert das System die Konfigurationsdatei sofort. Um diese Änderung wirksam zu machen, stoppt das Skript kurz die Funk-Dienste (OLED zeigt OFFLINE) und startet sie neu (OLED zeigt Initializing). Dein Hotspot ist danach sofort wieder mit den korrekten Einstellungen einsatzbereit.

Die Info-Analyse

Mit dem Aufruf ./dmr-chk info startest du eine tiefgreifende Systemanalyse. Das Tool durchleuchtet:

  • Station & Gateway: Frequenzen, Standort und grundlegende Parameter.
  • Datenbanken: Den exakten Füllstand lokaler DMR-ID, Brandmeister und DMR+ Listen sowie den Zeitpunkt des nächsten automatischen Updates.
  • Wächter-Historie: Überprüft das Log auf die letzte ausgeführte Aktion.
  • Brandmeister-Favoriten: Gleicht die im WPSD-Dashboard gespeicherten Favoriten-TGs mit der offiziellen Brandmeister-Liste ab. Inoffizielle oder fehlerhafte TGs (z.B. eigens angelegte Club-TGs) werden markiert.
  • Status-Matrix: Übersetzt die komplexen Rewrite-Regeln und Optionen in verständliches Funker-Deutsch (siehe Parameter Lexikon).

Automation & Lückenloses Logging

Der Automatische Nacht-Check (Cronjob)

Da nicht jeder Hotspot 24/7 überwacht wird, bietet das Tool eine optionale, komplett lautlose Automation. Mit dem Befehl ./dmr-chk install-cron installierst du einen täglichen Check, der jede Nacht um 03:00 Uhr die Integrität deiner Konfiguration prüft. (Deinstallation jederzeit mit ./dmr-chk remove-cron).

Die Login-Warnung: Findet der nächtliche Check eine Abweichung, verbraucht er keine Ressourcen für aufwendige Alarme. Stattdessen setzt er ein unsichtbares File-Flag. Sobald du dich das nächste Mal per SSH (Terminal) einloggst, explodiert eine rote Warnmeldung auf deinem Bildschirm und fordert dich auf, den Wächter auszuführen (siehe Praxis-Beispiele)!

Das Monats-Logbuch

Jeder Aufruf (egal ob manueller Wächter, Info-Analyse oder der nächtliche Cronjob) wird lückenlos und sauber im Verzeichnis /home/pi-star/ protokolliert.

  • Monats-Rotation: Das System legt jeden Monat automatisch eine neue Textdatei an (z.B. dmr-chk_log_2026-10.txt).
  • Auto-Archivierung: Zum Monatswechsel wird das alte Logbuch als komprimierte .zip-Datei in den Ordner dmr_log_archive verschoben.
  • Self-Cleaning: Archive, die älter als 365 Tage (1 Jahr) sind, werden vom Tool automatisch und rückstandsfrei vom Hotspot gelöscht, um SD-Karten-Speicherplatz zu schonen.

Professor-Modus: DMRGateway Parameter Lexikon

Mit dem Befehl ./dmr-chk info analysiert das Tool deine aktive Konfiguration und übersetzt die komplexen Maschinen-Codes in lesbares "Funker-Deutsch". Hier ist die Erklärung aller wichtigen System-Parameter:

Options-Kette (DMR+)

StartRef z.B. 4193
Der Reflektor, mit dem sich der Hotspot beim Booten (oder nach Inaktivität) standardmäßig verbindet. Ein Wert von 4000 bedeutet "unverbunden".
RelinkTime z.B. 120
Die Zeit in Minuten, nach der das System nach einem manuellen Wechsel automatisch wieder auf den StartRef zurückfällt.
TS1_x / TS2_x Statische TGs
Hierüber teilst du dem Master-Server mit, welche Sprechgruppen (Talkgroups) dauerhaft zu dir durchgeschaltet bleiben sollen.

Rewrite Routing-Regeln

TGRewrite
Leitet Gruppenrufe (Talkgroups) um. Simplex-Hotspots haben physisch nur Timeslot 2 (TS2). Wenn das weltweite Netz jedoch TS1 verlangt, wandelt diese Regel den Sende-Slot (2) in den Ziel-Slot (1) um.
PCRewrite
Das exakt gleiche Prinzip wie TGRewrite, jedoch ausschließlich für Privatrufe (Private Calls). Wird fast immer für Reflektor-Steuerungen (wie PC 4000 - 5000) genutzt.
TypeRewrite
Wandelt die Rufart um. Damit kann z.B. ein ankommender Privatruf (wie ein Echo-Dienst) auf dem Hotspot als Gruppenruf (Talkgroup) ausgegeben werden.
SrcRewrite
Schreibt die Absender-ID eines eintreffenden Rufs um. So "denkt" dein Funkgerät z.B., dass die Antwort eines Reflektors auf der gewohnten Talkgroup 9 stattfindet.

Die PassAll-Funktion

PassAllTG / PassAllPC: Wenn diese Parameter auf "1" oder "2" (für den jeweiligen Zeitschlitz) gesetzt sind, leitet das Gateway ALLE Rufe ungefiltert durch, auch wenn keine explizite Rewrite-Regel existiert.
Tipp vom Maintainer: Dies ist das Standard-Verhalten für WPSD Hotspots im Brandmeister Netz. Beachte jedoch, dass PassAll systemweit immer nur für ein einziges Netzwerk aktiviert sein sollte, sonst kann es zu Schleifen oder Konflikten kommen.
